
Modifications
=============


10/21/2026

Added Arxiv as a new search agent.
An "In Files" search on "Arxiv" reveals the affected code files.

Tested using only Arxiv repository.

Used the following user input:  
Question: What are ways to detect "fall armyworm" early? Instructions: - Restrict paper retrieval to the years 2023 through 2026 inclusive. - Where "fall armyworm" is used in a search, maintain that as a quoted phrase.

Review had three references. One reference did not have the download link. There were citations within the review. After several runs with more or less repositories in play, have found that, on this low-end equipment and small model, the fewer papers, the better the results. That is expected. Still, the reviews were very informative, although not directly publishable.

Added arxiv to the bottom of requirements.txt to enable Arxiv searches.


10/19/2026

In paper_discovery.py there is a line of code that starts with "for name, cls".
This loop lists and configures the sites to be searched.
Commented out semantic_scholar and core since each of those require an API key.
One can uncomment those if one wishes to subscribe to them. Be sure to update academic_config.py to add the API keys.

Added block of code to assist with tracing function calls pursuant to modification.
See top of Academic_Researcher.py for enabling or disabling the trace.



10/17/2026

Modified document_store.py and paper_discovery.py to change deprecated fitz library to pymupdf.
PyCharm Community reports pymupdf as having a security flaw but that flaw was fixed in commit b2c8f3a.
See https://www.mend.io/vulnerability-database/CVE-2026-82035/?utm_source=Jetbrains.

Modified Academic_Researcher.py in main() to enable all warnings.

Modified Academic_Researcher.py in print_banner() to replace print tabs with blanks.

Modified requirements.txt, Line 28 to read: pymupdf>=1.28.2 # security flaw has been fixed.
This ensures the latest install, the one that fixes the security flaw.
